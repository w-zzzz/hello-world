# 你下单时，到底发生了什么？

到这里你已经知道：价格不是单一数字，订单簿里挂满了等待撮合的意愿。那么当你在交易终端按下"买入"按钮，到底发生了什么？你**告诉系统的不是"我要买"，而是"我要按某种规则买"**——这个规则就叫 **订单类型 (order type)**。选错了订单类型，再好的策略也会被执行细节吃掉。

## 市价单 (Market Order) — 速度优先

最简单的订单：**"用当前最优价格立刻买（卖）这么多股"**。

```python
broker.submit_order(symbol="SPY", qty=100, side="buy", type="market")
```

执行逻辑：从订单簿最优卖价开始往上吃，直到 100 股填满。

- 优点：几乎一定能成交，速度快。
- 缺点：**你不知道最终成交价是多少**，全凭当时的订单簿深度。流动性差或新闻爆发时，滑点能让你怀疑人生。

适合：流动性很好的大盘股、你**真的需要立刻进出**的场景（比如止损触发后的清仓）。

## 限价单 (Limit Order) — 价格优先

"我最多愿意付 X 元"或"最少要卖 Y 元"。

```python
broker.submit_order(symbol="SPY", qty=100, side="buy",
                    type="limit", limit_price=420.50)
```

执行逻辑：

- 如果限价 ≥ 当前最优卖价，部分或全部立刻成交（这种叫 marketable limit order）；
- 否则挂到订单簿上，等对手方来"吃"你。

- 优点：**控制价格**，避免在错误的价位被填掉。
- 缺点：可能**永远不成交**——市场跑了你就在原地干瞪眼。

适合：你愿意为更好的价位牺牲成交确定性的所有场景，包括做市、网格、左侧建仓。

## 止损单 (Stop Order)

止损单的本质是 **"价格碰到某个触发线时，自动变成市价单"**。

```python
broker.submit_order(symbol="SPY", qty=100, side="sell",
                    type="stop", stop_price=415.00)
```

举例：你以 420 买入 SPY，挂了一个 415 的止损卖单。当 SPY 跌到 415 这条线，止损被"激活"，立刻按市价卖出。

注意它**不是"保证 415 卖出"**——只是"到 415 就触发市价卖出"。如果市场跳空跌到 410，你就以 410 附近的价格成交。

用法：限制单笔最大亏损；也可以反向做"突破买入"（buy stop）。

## 止损限价单 (Stop-Limit Order)

止损单的"控价"版本：触发后变成**限价单**，而不是市价单。

```python
broker.submit_order(symbol="SPY", qty=100, side="sell",
                    type="stop_limit",
                    stop_price=415.00, limit_price=414.50)
```

含义：跌到 415 触发；触发后挂一个"最低 414.50 卖出"的限价单。如果市场已经跳到 414 以下，你的单子就**挂着不成交**。

权衡：

- 比纯止损更可控（不会被极端跳空成交在惨不忍睹的价位）；
- 也可能在最需要离场的时候**根本没卖出去**，从而扛着更大的亏损。

## 高级订单：TWAP、VWAP、Iceberg（仅介绍）

机构和量化交易者经常用**算法订单 (algo order)** 把一笔大单拆成很多小单慢慢执行：

- **TWAP (Time-Weighted Average Price)**：按时间均匀切片。比如 10 万股在 1 小时内每分钟均匀下单，目标是成交均价接近这段时间的 TWAP。
- **VWAP (Volume-Weighted Average Price)**：按历史成交量分布切片，量大的时段下多、量小时下少。目标是接近当日 VWAP，这是机构最常用的执行基准。
- **Iceberg (冰山单)**：只在订单簿上显示一小部分挂单量，剩下的隐藏在水下。成交一部分后再露出新的一部分。目的是**避免被对手发现你的真实意图**。

这些算法订单 M4 我们会专门讲，这里先有印象即可。

## 每种订单的「坑」

<Pitfall title="不要在低流动性时段用市价单">**周末刚开盘、深夜、消息发布瞬间**——这些时候订单簿往往很薄。你的市价单可能在 1 秒内把价格打穿好几个档位，滑点能达到正常情况的几十倍。哪怕牺牲一点确定性，也尽量改用 marketable limit order（限价比对手价高几跳）。</Pitfall>

<KeyPoint title="止损不是保险">止损单只承诺"触发"，**不承诺成交价**。跳空、停牌、闪崩时，你的止损位会被大幅穿透。要对最大亏损负责的是仓位大小，而不是止损价位本身。</KeyPoint>

## 决策树：什么场景用哪种？

<Reveal summary="点击展开：常用订单选择决策树">
```text
开始
 │
 ├─ 我必须立刻成交吗？
 │    ├─ 是 → 流动性好？
 │    │       ├─ 是 → 市价单 (Market)
 │    │       └─ 否 → marketable 限价单（限价 ≈ 对手价 + 几跳）
 │    └─ 否 → 我对成交价有明确要求吗？
 │            ├─ 是 → 限价单 (Limit)
 │            └─ 否 → 但我要在某个价位被动触发？
 │                    ├─ 控价不重要 → 止损单 (Stop)
 │                    └─ 控价重要   → 止损限价单 (Stop-Limit)
 │
 └─ 单子量是否远大于平均挂单深度？
      └─ 是 → 上算法单 (TWAP / VWAP / Iceberg)
```

口诀：
- **市价 = 拿成交换价格**；
- **限价 = 拿价格换成交**；
- **止损 = 触发，不是保证**；
- **算法单 = 把大象切成小块进门**。
</Reveal>
