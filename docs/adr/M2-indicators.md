# ADR M2 — Indicator playground (5 indicators, Python↔TS parity)

**Status:** Accepted
**Date:** 2026-05-25
**Milestone:** M2 (5 indicators + playground + bidirectional parity CI)

## Context

M0/M1 shipped infrastructure and the first three lessons. M2 introduces the first cluster of real **quant pedagogy primitives**: five canonical technical indicators (SMA, EMA, RSI, MACD, Bollinger Bands), each with a metadata-driven interactive playground, and — critically — a **two-implementation parity contract** between the Python canonical implementation (`python/qa_indicators`) and a TypeScript mirror used in the browser (`packages/indicators-ts`).

The parity rule is the single most important architectural commitment in this milestone: anyone who modifies an indicator must touch **both** implementations, regenerate golden fixtures, and pass the CI parity check (`1e-9` absolute / `1e-6` relative tolerance). This rule scales across the 30+ indicators that will land in M7.

## Decisions

### 1. Indicators in scope

| id | name | params (defaults) | outputs |
|---|---|---|---|
| `sma` | Simple Moving Average | `period: 20`, `source: 'close'` | overlay `sma` |
| `ema` | Exponential Moving Average | `period: 20`, `source: 'close'` | overlay `ema` |
| `rsi` | Relative Strength Index | `period: 14`, `source: 'close'` | panel `rsi` (0..100) |
| `macd` | Moving Average Convergence/Divergence | `fast: 12`, `slow: 26`, `signal: 9`, `source: 'close'` | panel `macd`, `signal`, `histogram` |
| `bollinger` | Bollinger Bands | `period: 20`, `stddev: 2`, `source: 'close'` | overlay `middle`, `upper`, `lower` |

EMA uses recursive smoothing with α = 2/(period+1). RSI uses **Wilder's smoothing** (α = 1/period) — matches the original Wilder 1978 formula and TA-Lib default. MACD = EMA(fast) − EMA(slow); signal = EMA(macd, signal_period); histogram = macd − signal. Bollinger middle = SMA(period); upper/lower = middle ± stddev × σ_period (sample std dev, ddof=0 to match pandas-ta default).

### 2. Golden-fixture format

A single 252-bar deterministic SPY-like daily OHLCV input is the parity input:
- File: `python/qa_indicators/qa_indicators/fixtures/parity_input.json`
- Format: `{ bars: Bar[] }` where `Bar = { t, open, high, low, close, volume }`
- Source: Python-side mulberry32 + Box-Muller mirror of the TS `generateSpyDaily(seed=42)` function — but capped at 252 bars and committed as JSON so neither side has to re-derive.

Each indicator's golden outputs live at `python/qa_indicators/qa_indicators/fixtures/golden/<id>.json`:
```json
{
  "indicator": "rsi",
  "params": { "period": 14, "source": "close" },
  "input": "parity_input.json",
  "tolerance": { "abs": 1e-9, "rel": 1e-6 },
  "outputs": {
    "rsi": [null, null, ..., 52.34, 51.99, ...]
  }
}
```
Generated by `python/qa_indicators/qa_indicators/scripts/regenerate_golden.py`. Re-run after any indicator change.

NaN/leading-window values serialize as `null` in JSON.

### 3. Python implementation (`python/qa_indicators`)

Each indicator lives in its own module with the same contract:

```python
import pandas as pd
from qa_core.schemas import IndicatorMeta

META: IndicatorMeta = IndicatorMeta(...)

def compute(df: pd.DataFrame, period: int = 14, source: str = "close") -> pd.DataFrame:
    """Returns a DataFrame indexed identically to df with the indicator's named columns."""
```

Files:
- `sma.py` (exists from M0)
- `ema.py`
- `rsi.py`
- `macd.py`
- `bollinger.py`
- `registry.py` — auto-collects all `META` exports

Registry assembly stays simple: `REGISTRY = {m.id: m for m in [SMA_META, EMA_META, RSI_META, MACD_META, BOLLINGER_META]}`.

Property tests (`tests/test_<id>.py`) using `hypothesis`:
- SMA / EMA of a constant series equals the constant after the warm-up window.
- SMA / EMA output length equals input length; first `period-1` values are NaN.
- RSI ∈ [0, 100] everywhere it isn't NaN.
- MACD histogram = macd − signal.
- Bollinger upper ≥ middle ≥ lower.
- Bollinger collapses to middle when input is constant (stddev = 0).

### 4. TypeScript mirror (`packages/indicators-ts` — new package)

Pure TS, no pandas, no extra deps. Each indicator exposes:

```ts
export interface IndicatorInput { bars: Bar[]; params: Record<string, unknown> }
export interface IndicatorResult { [outputName: string]: (number | null)[] }
export function compute(input: IndicatorInput): IndicatorResult;
```

Files mirror Python module names: `src/sma.ts`, `src/ema.ts`, `src/rsi.ts`, `src/macd.ts`, `src/bollinger.ts`, plus `src/index.ts` exporting `INDICATORS: Record<string, ComputeFn>`.

Vitest tests load the golden JSON files (via a workspace path import) and assert outputs match within tolerance.

### 5. Parity script (`scripts/check-indicator-parity.ts`)

Standalone tsx script:
1. Iterates `INDICATORS` keys.
2. For each, loads `python/qa_indicators/qa_indicators/fixtures/golden/<id>.json`.
3. Loads `python/qa_indicators/qa_indicators/fixtures/parity_input.json` once.
4. Runs the TS compute function with the golden's `params`.
5. Compares each output column element-wise against golden, asserting:
   - Both null OR both numeric.
   - `|a - b| <= max(abs_tol, rel_tol * max(|a|, |b|))`.
6. Exits 1 on first mismatch (with a precise diff: indicator, output, index, expected, got).

Invoked via `pnpm run check:parity` (root). Replaces the `parity-check` CI placeholder job.

### 6. Indicator metadata contract (IndicatorMeta) — already defined in `qa_core.schemas`

Re-used as-is. Each indicator's `META` populates:
- `formula_tex` (LaTeX, no `$$`)
- `params` (ParamSpec map with kind/default/min/max/step/options)
- `outputs` (overlay vs panel, range hint)
- `use_cases_keys` and `pitfalls_keys` (i18n keys; actual strings authored in M7)

Drive `<IndicatorPlayground>` UI generation entirely from this schema.

### 7. `<IndicatorPlayground>` component (replaces M2 stub in `packages/content`)

Client component. Auto-renders from `IndicatorMeta`:
- One range slider per `INT`/`FLOAT` param
- One select per `ENUM` param
- A `<Chart>` with the indicator's series rendered as the matching overlay (line for SMA/EMA/middle/upper/lower; band for Bollinger upper/lower; secondary panel for RSI/MACD — for M2 simplify to a stacked second chart)
- A KaTeX-rendered formula via `<MathBox>`
- A "Reset" button restoring defaults
- A "Verify against server" button (calls `POST /indicators/{id}/compute`, overlays the API-returned series in a dashed style, computes max abs delta vs the local TS computation, displays it)

The component lives in `packages/content/src/components/IndicatorPlayground.tsx` (replacing the stub in `components/index.tsx`).

### 8. API endpoint (`apps/api/qa_api/routes/indicators.py`)

Augment the existing stub with:

```python
@router.get("/", response_model=list[IndicatorMeta])
async def list_indicators() -> list[IndicatorMeta]: ...

@router.post("/{indicator_id}/compute", response_model=ComputeIndicatorResponse)
async def compute_indicator(indicator_id: str, body: ComputeIndicatorRequest) -> ComputeIndicatorResponse: ...
```

Request/response schemas added to `python/qa_core/qa_core/schemas.py`:

```python
class ComputeIndicatorRequest(StrictModel):
    bars: list[Bar]
    params: dict[str, str | int | float]

class ComputeIndicatorResponse(StrictModel):
    indicator: str
    params: dict[str, str | int | float]
    outputs: dict[str, list[float | None]]
```

The handler:
1. Looks up the indicator in `REGISTRY`; 404 if unknown.
2. Validates params against the indicator's metadata.
3. Converts `bars` to a pandas DataFrame.
4. Calls the indicator's `compute(df, **params)`.
5. Serializes the result, converting NaN to `None` for JSON.

Add `test_indicators.py` with FastAPI TestClient: lists indicators, computes RSI on the parity fixture, asserts the output matches the golden (acts as a server-side mirror of the TS parity check — third independent witness).

### 9. Frontend routes

- `apps/web/app/[locale]/indicators/page.tsx` — grid of 5 indicator cards; click → playground page.
- `apps/web/app/[locale]/indicators/[id]/page.tsx` — full-screen playground.

i18n keys added: `indicators.title`, `indicators.subtitle`, `indicators.reset`, `indicators.verifyServer`, `indicators.maxDelta`, `indicators.serverErr`, `indicators.coming.M7` (for the 25 remaining unimplemented indicators rendered as locked tiles).

### 10. CI integration

Replace the `parity-check` job in `.github/workflows/ci.yml` to:
1. Set up pnpm + node.
2. Set up uv.
3. `pnpm install --frozen-lockfile`.
4. `uv sync`.
5. `uv run python -m qa_indicators.scripts.regenerate_golden --verify` — re-derives goldens, fails if they differ from committed JSON (catches stale golden files).
6. `pnpm exec tsx scripts/check-indicator-parity.ts` — runs TS parity.

Total time target: ≤ 90 seconds.

### 11. Path conventions for parallel agents (locking file boundaries)

| Agent | Exclusive write paths |
|---|---|
| Python-indicators | `python/qa_indicators/qa_indicators/{ema,rsi,macd,bollinger,registry,scripts}.py`, `python/qa_indicators/qa_indicators/fixtures/**`, `python/qa_indicators/tests/test_{ema,rsi,macd,bollinger}.py`, `python/qa_core/qa_core/schemas.py` (additive: ComputeIndicatorRequest/Response) |
| TS-indicators | `packages/indicators-ts/**` |
| API | `apps/api/qa_api/routes/indicators.py`, `apps/api/tests/test_indicators.py` |
| Frontend | `apps/web/app/[locale]/indicators/**`, `packages/content/src/components/IndicatorPlayground.tsx`, `packages/content/src/components/index.tsx` (additive edit), `packages/i18n/src/messages/{zh,en}/common.json` (additive keys for indicators.*) |
| Parity+CI | `scripts/check-indicator-parity.ts`, `.github/workflows/ci.yml` (replace `parity-check` job body), root `package.json` (additive script `check:parity`) |

Boundary contract for `python/qa_core/qa_core/schemas.py`: **only the Python-indicators agent edits it** (adds the two request/response models at the end of the file). All other agents that need those types should import them — including the API agent.

### 12. Wave plan

One wave, five parallel agents (worktree-isolated):

1. **python-indicators** — implementations + fixtures + golden generator + property tests
2. **ts-indicators** — new package with all 5 mirrors + vitest tests against goldens
3. **api** — compute endpoint + tests
4. **frontend-playground** — IndicatorPlayground component + indicators routes + i18n keys
5. **parity-ci** — parity script + CI replacement + root script

After all merge, run full validation locally, push, verify CI.

## Exit criteria

1. `pnpm run check:parity` exits 0 on a clean checkout.
2. `uv run pytest python/qa_indicators` passes (≥ 6 tests per indicator via hypothesis).
3. `uv run pytest apps/api` passes — including the new compute endpoint third-witness test.
4. `pnpm --filter web build` succeeds with new indicator routes statically generated.
5. Visit `/zh/indicators/rsi` — sliders for period/source render; sliding period live-updates the chart in < 50ms; "Verify against server" overlays a dashed line and shows a delta < tolerance.
6. CI `parity-check` job runs the real parity script (no longer a stub) and passes.
7. All five indicators show up in `/zh/indicators` grid.
8. Lint + typecheck + tests + build green in CI.
