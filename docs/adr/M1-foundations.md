# ADR M1 — Track A foundations + chart primitives + i18n

**Status:** Accepted
**Date:** 2026-05-25
**Milestone:** M1 (Track A first 3 lessons + chart primitives + i18n)

## Context

M0 established the monorepo skeleton. M1 ships the first vertical slice of real product value: a working lesson reader, the canonical chart primitive, three bilingual lessons (A-01..A-03), and a basic command palette. After M1 a user can visit `/zh/lessons` (or `/en/lessons`), pick a lesson, read narrative content, see an interactive K-line chart of SPY, take a quick quiz, and switch locale without losing context.

This milestone is the first that requires multi-agent content authors to work in parallel with infrastructure agents. The MDX component contracts defined here MUST be respected by all agents so their work integrates cleanly at merge time.

## Decisions

### 1. Chart primitive

- **Library:** [`lightweight-charts` v5.x](https://tradingview.github.io/lightweight-charts/) from TradingView. Free MIT-licensed, ~45KB gzipped, great perf on 10y daily bars.
- **Wrapper package:** `packages/charts`. Exposes a single canonical `<Chart>` plus a small `<MiniChart>` for cards.
- **Sample data:** For M1 we ship a deterministic synthetic SPY-like daily OHLCV series (≈504 bars ≈ 2 years) generated by a seeded RNG. Real data ingestion lands in M5.
- **Theming:** Reads CSS variables (`--color-bull-500`, `--color-bear-500`, `--color-foreground`, `--color-card`) via `getComputedStyle` so it auto-adapts to dark/light. Re-creates the chart on theme change.
- **SSR:** Client component (`"use client"`). Renders a fixed-height skeleton during SSR.

#### `<Chart>` props contract
```ts
type Bar = { t: string; open: number; high: number; low: number; close: number; volume: number };
type Overlay =
  | { kind: 'line'; data: { t: string; v: number }[]; color?: string; lineWidth?: 1|2|3; title?: string }
  | { kind: 'band'; upper: { t: string; v: number }[]; lower: { t: string; v: number }[]; color?: string; title?: string };

interface ChartProps {
  data?: Bar[];                 // if omitted, falls back to sample SPY
  symbol?: string;              // display only for M1; real symbol routing in M5
  height?: number;              // default 360
  overlays?: Overlay[];
  showVolume?: boolean;         // default true
  intervalLabel?: string;       // 'D'|'1H'|... display only
  className?: string;
}
```

#### `<MiniChart>` props contract
```ts
interface MiniChartProps { data?: Bar[]; height?: number; className?: string }
```

### 2. Content package & MDX infrastructure

- **Package:** `packages/content`. Owns curriculum manifest, MDX component registry, lesson loader.
- **Curriculum manifest:** Full 110-lesson skeleton declared up-front (id, trackId, module, order, difficulty, durationMin, xp, prerequisites, tags). M1 only ships MDX for A-01/02/03; the rest are scaffolded metadata only and render a "Coming soon" placeholder lesson body.
- **Lesson directory layout:**
  ```
  packages/content/lessons/<TRACK>/<module>/<id>/
    meta.ts
    lesson.zh.mdx
    lesson.en.mdx
  ```
- **Loader:** `getLesson(id: string, locale: 'zh'|'en')` returns `{ meta, MDX }`. Uses dynamic import; lessons are statically discoverable at build via a generated `lessons.generated.ts` index produced by a tiny build script (`scripts/generate-lesson-index.ts`).
- **MDX runtime:** `@mdx-js/loader` + `@mdx-js/react` + `remark-math` + `rehype-katex`. Wired into Next 16 via `@next/mdx` plugin. KaTeX CSS imported once in lesson layout.

#### Lesson `meta.ts` contract

#### MDX components contract (frozen for M1)

| Component | Signature | Notes |
|---|---|---|
| `<Chart>` | (see above) | Re-exported from `@quant-academy/charts` |
| `<MiniChart>` | (see above) | Re-exported from `@quant-academy/charts` |
| `<MathBox>` | `{ display?: boolean; children: string }` | Renders `$$...$$` or `$...$` via KaTeX. `children` must be raw TeX. Block display by default. |
| `<Pitfall>` | `{ title?: string; children: ReactNode }` | Yellow-bordered callout. Heading defaults to `t('mdx.pitfall.title')`. |
| `<KeyPoint>` | `{ title?: string; children: ReactNode }` | Blue-bordered callout. Heading defaults to `t('mdx.keypoint.title')`. |
| `<Quiz>` | `{ id: string; question: string; options: string[]; answer: number; explanation: string }` | Single-select multiple choice. Stores result in localStorage under `qa.quiz.<id>`. Reveals explanation on submit. No backend yet (M3). |
| `<Reveal>` | `{ summary: string; children: ReactNode }` | Click-to-reveal accordion. |
| `<Compare>` | `{ left: ReactNode; right: ReactNode; leftTitle?: string; rightTitle?: string }` | Two-column side-by-side. |
| `<Glossary>` | `{ term: string; children: ReactNode }` | Inline tooltip; M1 ships static text (full glossary registry in M7). |

Components are **automatically available** in all MDX files via the central `MDXProvider`/`useMDXComponents` — authors do NOT import.

The following are **NOT available in M1** (placeholders if invoked — render a styled "available in M<N>" badge): `<IndicatorPlayground>` (M2), `<TryIt>` (M6), `<Backtest>` (M5).

### 3. Curriculum schema (Zod-validated)

```ts
// packages/content/src/schema.ts
import { z } from 'zod';

export const TrackIdSchema = z.enum(['A','B','C','D','E','F','G','H']);
export const DifficultySchema = z.enum(['beginner','intermediate','advanced']);

export const LessonMetaSchema = z.object({
  id: z.string().regex(/^[A-H]-\d{2}-[a-z0-9-]+$/),
  trackId: TrackIdSchema,
  module: z.string(),
  order: z.number().int().positive(),
  difficulty: DifficultySchema,
  durationMin: z.number().int().positive(),
  xp: z.number().int().positive(),
  prerequisites: z.array(z.string()).default([]),
  tags: z.array(z.string()).default([]),
  contributors: z.array(z.string()).default([]),
});
export type LessonMeta = z.infer<typeof LessonMetaSchema>;

export const TrackMetaSchema = z.object({
  id: TrackIdSchema,
  titleKey: z.string(),
  descriptionKey: z.string(),
  color: z.string(),                // tailwind color name (e.g. 'sky')
  order: z.number().int(),
});
export type TrackMeta = z.infer<typeof TrackMetaSchema>;

export function defineLesson(meta: LessonMeta): LessonMeta {
  return LessonMetaSchema.parse(meta);
}
```

### 4. Routing (apps/web)

New routes under `apps/web/app/[locale]/`:
- `/lessons` — track explorer: 8 track cards with completion percent (0% in M1).
- `/lessons/[trackId]` — module/lesson list for a track.
- `/lessons/[lessonId]` — lesson viewer. Catches the lesson id pattern.

Lesson viewer layout:
```
+----------------------------------------------+
| breadcrumb · progress bar · locale switch    |
+--------------------------------+-------------+
| narrative (MDX) ·············· | tutor stub  |
|                                | (placeholder)|
|                                |             |
+--------------------------------+-------------+
| prev lesson · next lesson · "mark complete"  |
+----------------------------------------------+
```

Mobile collapses tutor rail into a sheet.

### 5. Command palette (cmd-K stub)

- Library: `cmdk` 1.x.
- Triggered by `⌘K` / `Ctrl+K`. Actions:
  - Search lessons (by id, by title — uses curriculum manifest)
  - Toggle theme
  - Switch locale
  - Go to: dashboard, tracks, indicators (stub), workshop (stub), profile (stub)
- Rendered via a single `<CommandPalette>` mounted in `[locale]/layout.tsx`.
- Not yet hooked to user history / AI tutor — those land in M4/M11.

### 6. Landing page upgrade

Replace the placeholder chart slot on `/[locale]` with a real `<MiniChart>` of the sample SPY data, animated entry with framer-motion. The three feature cards link to: `/lessons` (track explorer), `/indicators` (stub 404-friendly), `/tutor` (stub).

### 7. Path conventions for parallel agents (locking file boundaries)

| Agent | Exclusive write paths |
|---|---|
| Charts | `packages/charts/**` |
| Content infra | `packages/content/src/**`, `packages/content/package.json`, `packages/content/tsconfig.json`, `apps/web/mdx-components.tsx`, `apps/web/next.config.ts` (MDX wiring only) |
| Frontend routing | `apps/web/app/[locale]/lessons/**`, `apps/web/app/[locale]/page.tsx` (landing update only), `apps/web/app/[locale]/layout.tsx` (cmd-K mount only), `apps/web/components/command-palette.tsx`, `apps/web/components/lesson-*.tsx` |
| Content zh | `packages/content/lessons/A/fundamentals/A-01-*/lesson.zh.mdx`, `packages/content/lessons/A/fundamentals/A-02-*/lesson.zh.mdx`, `packages/content/lessons/A/fundamentals/A-03-*/lesson.zh.mdx` (+ each lesson's `meta.ts` — first writer wins, ADR sets the canonical content) |
| Content en | Same paths but `lesson.en.mdx` |

`meta.ts` files live in the lesson dirs. Both zh and en agents create the lesson dir; **only the zh agent writes `meta.ts`**. en agent just creates `lesson.en.mdx` and trusts zh agent for `meta.ts`. (zh agent runs first conceptually; with worktrees they run truly in parallel — at merge time we resolve by accepting zh's `meta.ts`.)

To avoid the meta.ts race entirely, this ADR also specifies the **exact `meta.ts` contents** below — both agents will produce byte-identical files, so merge is trivial.

## Exit criteria

1. Visit `/zh/lessons` and `/en/lessons` — see all 8 tracks with proper bilingual titles + colored badges.
2. Visit `/zh/lessons/A` — see modules + lessons for Track A (3 real, others scaffolded).
3. Visit `/zh/lessons/A-01-what-is-market` — see full bilingual lesson with `<Chart>` rendered, KaTeX math, at least one `<Quiz>`, at least one `<Pitfall>`.
4. Locale switcher swaps lesson language **without** losing scroll/state.
5. `⌘K` opens command palette; "go to A-02" navigates correctly.
6. Landing page `/zh` and `/en` shows a `<MiniChart>` instead of the previous placeholder.
7. CI fully green: lint + typecheck + tests + build.
8. Visual: dark mode renders chart with bull/bear colors that contrast properly on dark bg.

## Parallel execution

Five worktree-isolated agents, all spawned in a single message:

| Agent | Branch suffix | Path scope |
|---|---|---|
| Charts | M1-charts | `packages/charts/**` |
| Content-infra | M1-content-infra | `packages/content/src/**`, `apps/web/mdx-components.tsx`, MDX wiring in `apps/web/next.config.ts` |
| Frontend | M1-frontend | lesson routes, landing update, cmd-K, lesson viewer components |
| Content-zh | M1-content-zh | 3 lessons × `lesson.zh.mdx` + `meta.ts` |
| Content-en | M1-content-en | 3 lessons × `lesson.en.mdx` |

Merge order at end: charts → content-infra → frontend → content-zh → content-en. Conflicts expected only in `apps/web/next.config.ts` (resolved by hand, both edits orthogonal).
