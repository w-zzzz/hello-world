Coding agents went from research demos to a daily tool for millions of
software engineers in roughly 18 months. The pace surprised even the
researchers who built them. By mid-2025 the best agents were closing more
than two-thirds of real GitHub issues on SWE-bench Verified, doing work that
was inconceivable when the benchmark launched in late 2023.

This module is about the design space — the architectural choices that
distinguish IDE-resident from autonomous agents — and the benchmarks that
actually measure progress. Pick the right tool for the right loop length.

## Two design points

The first axis to disentangle is **who closes the loop**.

**IDE-resident agents** (Cursor, GitHub Copilot Chat, Continue, Cody,
Windsurf) keep a human inline. The model proposes edits; the human reviews
and accepts. The most powerful versions integrate multi-file edits, repo-wide
context, and a chat sidebar, but the *unit of work* is one human-approved
edit at a time.

**Autonomous agents** (Devin, Claude Code, OpenAI Codex 2025, OpenHands,
SWE-agent) plan, execute, and iterate over many turns before returning. They
own a shell. They run tests. They read stack traces and try again. The
human signs off at the end — sometimes after hours of work.

The trade-off is the usual oversight-vs-leverage one. Inline agents are
safer, faster on small edits, easier to course-correct. Autonomous agents
are higher leverage on multi-step tasks but harder to oversee and
catastrophically wrong if their plan is bad.

## The agent-computer interface (ACI)

SWE-agent's central insight (Yang et al. 2024) was that the *interface*
matters as much as the model. Give the agent purpose-built tools — `find
file`, `view file with line numbers`, `edit lines`, `run tests` — designed
for an LLM's context window and error-handling style, and performance jumps
dramatically with no model change.

Modern autonomous coding agents now standardize on something close to
SWE-agent's ACI:

- **File-system tools**: `read`, `edit`, `write`, with line-level addressing.
- **Shell**: `bash` with timeouts, output truncation, working-directory state.
- **Search**: `grep`/`ripgrep`, semantic search over the repo.
- **Browser**: for fetching docs (Claude Code uses MCP servers for this).
- **Process control**: start/stop background processes, view logs.

The MCP standard (Anthropic, late 2024) is the lingua franca for plugging
these tools into any agent host. In practice this means an MCP server for
your GitHub, your Sentry, your Linear, your CI — any agent that speaks MCP
inherits them all.

## The benchmark layer

Two benchmarks dominate practical evaluation in 2025-26:

1. **SWE-bench Verified** (Princeton + OpenAI). 500 hand-filtered real GitHub
   issues from popular Python repos; the agent must produce a patch that
   passes the project's hidden test suite. Measures end-to-end bug-fixing.
2. **Aider polyglot** (Paul Gauthier). 225 Exercism-style problems across
   Python, JavaScript, Go, Rust, C++, Java, Swift. Measures edit-format
   compliance and localization in addition to raw correctness.

A typical 2025 leaderboard looks like:

| Agent + model | SWE-bench Verified | Aider polyglot |
|---|---|---|
| Claude Code + Claude 4 Opus | ~75% | ~85% |
| OpenAI Codex 2025 + GPT-5 | ~74% | ~84% |
| Devin + Claude/GPT mix | ~72% | n/a |
| Open-weights leader (DeepSeek-V3.1 / R1.5) | ~62% | ~75% |

These numbers move every quarter — treat them as snapshots. The interesting
thing is the *gap* has narrowed: open models trail closed ones by maybe ten
points instead of forty.

## What good agentic coding looks like

A few patterns reliably separate good agents from bad:

- **Read before you write.** Strong agents spend most of their tokens reading
  source. Weak ones jump to edits.
- **Run tests early and often.** A failing test is the most informative
  observation an agent can get. Bad agents skip the test step and "ship"
  patches that don't compile.
- **Localize precisely.** Knowing which file and which function is more than
  half the battle. Search, find-references, and ast-grep are underrated.
- **Surface uncertainty.** A frontier agent should ask the user when the spec
  is ambiguous, not silently pick a path. (This is one of the hardest things
  to train.)

```python
# A sketch of the inner loop most autonomous coding agents run.
state = init(task, repo)
while not done(state):
    obs = render_state(state)             # files, recent commands, test output
    plan = model.think(obs, history)      # often hidden reasoning tokens
    action = model.choose_tool(plan)      # file edit, shell command, etc.
    result = execute(action)
    state = update(state, action, result)
    if budget_exceeded(state) or stuck(state):
        ask_user_or_abort()
```

## Where this is going

Three trends shape the next year:

1. **Longer horizons.** Multi-day agent runs ('build me this feature, open
   the PR, address review comments') are now a serious research target.
   This needs better memory, better planning, and better evaluation.
2. **Sandboxing as a product.** Cognition's VM, OpenAI's Operator-style
   browser, Anthropic's Computer Use — secure remote execution
   environments are becoming the substrate.
3. **Verifier-grounded RL.** Coding is the perfect domain for RL: tests are
   automated rewards. DeepSeek-R1 already used this for math; expect a
   wave of code-RL'd models in 2026.

<Callout variant="insight" title="The 70% problem">
SWE-bench Verified scores plateaued near 75% through late 2025. The
remaining 25% is genuinely hard: cross-file refactors, ambiguous specs,
flaky tests, environment setup. Pushing past that ceiling requires
better tools and better evaluation, not just bigger models.
</Callout>
