In 2020, GPT-3 demonstrated something the field had not seen before: a
language model that could *learn from a few examples in its prompt* —
arithmetic, translation, classification — without any gradient update.
This is in-context learning (ICL). It is the capability that turned LLMs
from autocomplete into general-purpose problem solvers.

## Why this matters

ICL is the reason a single API call can do so much. Without it, every
new task would require fine-tuning. With it, you can specify a task by
showing a handful of examples — and the model "gets it." The phenomenon
is also a window into how Transformers actually use their parameters,
because nothing is being updated.

## The setup

A few-shot prompt looks like:

```
English: hello → French: bonjour
English: cat   → French: chat
English: book  → French: ?
```

The model completes with `livre`. No fine-tuning happened. The mapping
"English → French" is inferred from the in-context examples, which
specify the *task*, while the parameters that were learned during
pretraining specify *how to apply such tasks*.

Brown et al. quantified this systematically: zero-shot, one-shot, and
$k$-shot performance, varying with model size. The headline finding —
$k$-shot accuracy improves dramatically with scale, far past where
zero-shot stops improving — was the empirical foundation of the LLM era.

## What is happening mechanically?

Two complementary stories.

### The mechanistic story: induction heads

Olsson et al. (2022) identified **induction heads**: a circuit of two
attention heads that

1. The first writes the previous token into the next position's
   residual stream.
2. The second, at the current position, queries for a previous
   occurrence of the current token, and copies whatever came *after* it.

This is exactly the algorithm for "if I saw `A B ... A`, predict `B`."
The circuit emerges abruptly during training. ICL ability — measured by
loss on contexts where it should help — improves abruptly at the same
training step. It is the cleanest known instance of a capability
appearing because a specific mechanism appeared.

### The meta-learning story

A different perspective: pretraining on diverse data is *implicit
meta-learning*. Each document specifies a task (a topic, a register, a
language); the model's job is to figure out which task and continue. ICL
is this same skill, applied in real time to a prompt that explicitly
displays examples.

Several papers — von Oswald et al., Akyürek et al., Garg et al. — show
that on simple regression tasks, a Transformer's in-context performance
matches one or more steps of gradient descent on the in-context examples,
implemented entirely in activations. The model is, in a real sense,
"running an optimizer in its head."

<Callout variant="insight" title="No backprop at inference">
The forward pass alone is computing something that *behaves like*
learning. This does not mean weights update. It means the right linear
algebra in attention layers can simulate one optimization step over
the few-shot examples — a striking expressiveness result.
</Callout>

## Emergence — and the asterisk

Wei et al. (2022) called many ICL abilities **emergent**: below a
threshold scale, the model is at chance; above it, performance jumps to
non-trivial. The list included multi-step arithmetic, code generation,
and long-form reasoning.

Schaeffer et al. (2023) pushed back hard. Their argument: many "sudden
jumps" are artifacts of *discontinuous metrics* (exact-match, parsed
correctness) applied to *smoothly improving* underlying skills. Switch
to log-probability of the correct token and the curve is smooth.

The honest synthesis:

- Some abilities show genuinely abrupt phase transitions even on smooth
  metrics (induction-head emergence is one).
- Some look emergent but are measurement artifacts.
- "Emergent" is a useful descriptor for the *user-facing* behavior;
  whether the underlying capability is smooth or genuinely phase-
  transitioning is task-dependent.

```python
# A toy ICL probe: can the model do a synthetic linear function from k examples?
import numpy as np
np.random.seed(0)
W = np.random.randn(4)            # ground-truth task
xs = np.random.randn(8, 4)
ys = xs @ W
prompt = "\n".join(f"{x} -> {y:.3f}" for x, y in zip(xs[:6], ys[:6]))
prompt += f"\n{xs[6]} -> ?"
# Send `prompt` to your LLM; compare the model's float against ys[6].
```

The pattern of which $k$ are needed and how performance scales with model
size is one of the standard probes in ICL research.

## What ICL is not

A few common misconceptions worth retiring:

- **It is not memorization.** Garg et al. show ICL works on tasks the
  model demonstrably never saw at training (random linear regressions
  with held-out distributions).
- **It is not a substitute for fine-tuning** when you have data.
  Fine-tuning still wins for narrow, repeated tasks; ICL wins for
  one-off, low-data, or rapidly changing ones.
- **It is not unlimited.** Long-context retrieval is famously
  unreliable in the middle of the context ("lost-in-the-middle") and
  ICL accuracy degrades with too many or noisy examples.

<Callout variant="aside" title="ICL is the foundation of agents">
Every modern agent loop — ReAct, tool-using assistants, scratchpad
reasoning — is built on ICL. The user provides the task description;
recent observations update the conditioning. Without ICL, you would
need to fine-tune for each new tool.
</Callout>
